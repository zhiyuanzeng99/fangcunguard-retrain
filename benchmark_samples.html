Policy 能解决这些问题吗

ConvAbuse 无法用 Policy 解决
根本原因：架构不匹配。 ConvAbuse 评测的是对话级别的 abuse，而我们是单轮文本分类器。"what?" 这条文本任何 policy 规则都无法判定为有害，因为信息根本不在文本里。VirtueGuard 应该是把整段对话历史一起输入。
  • ✗关键词 / 正则 rules：无效，unsafe 样本大多是无害短语
  • ✗调低 threshold：会把所有文本都判 unsafe，FPR 爆炸
  • ✗加 ConvAbuse 训练数据：标注体系和我们不兼容，反而降低其他 benchmark
  • →真正的解法：输入层传入对话历史（架构改动）
HarmfulQA 可以部分改善
根本原因：阈值过高 + 训练数据覆盖不足。 明确有害的问题（DNS spoofing、seizure）unsafe_score 约在 0.5–0.65，thr=0.70 刚好截掉了这批。模糊样本（nuclear physics）本身就不该拦，是数据集噪声。
  • ✓针对 cybersecurity / crimes 类降低 per-class thr（已有机制）
  • ✓加 hard rules：attack / exploit / how to hack 等关键词 → 强制 unsafe
  • ✓补 HarmfulQA 风格训练数据（直接式有害问题）
  • →模糊样本（nuclear physics）不应拦，属数据集噪声，不追求 100% recall
OpenAI Moderation FPR 18.7% 可以改善
根本原因：对 subtle 英文内容过度误报。 模型见过的英文 safe 样本不够多样，偏向把英文问题判为 unsafe。
  • ✓加英文 safe 训练数据（WildGuardMix / XSTest）
  • ✓soft rules：教育 / 学术 context 降低 unsafe_score
  • →本质需要更多英文 benign 数据，rule 只能微调
HarmBench Recall 59.4%@0.5 需要训练数据
根本原因：320 个样本 unsafe_score 集中在 0.5–0.65，thr=0.70 全漏。 降低全局阈值会让 FPR 爆炸，需要针对性 per-class 调整或加训练数据。
  • ✓crimes / cybersecurity per-class thr 降到 0.45–0.50
  • ✓加 HarmBench 风格合成数据（直接指令式有害）
  • ✗全局 thr 降低：BeaverTails FPR 会进一步恶化
综合建议
ConvAbuse 暂时放弃对标——架构不兼容，这个 benchmark 本身要求对话历史，和我们的单轮设计不匹配，VirtueGuard 的 F1 0.808 是在不同条件下取得的。

HarmfulQA / HarmBench 改善路径：①调低 crimes + cybersecurity per-class thr 到 0.45；②加 hard rules 覆盖明确攻击指令；③补 Aegis 2.0 + HarmfulQA 风格训练数据（预计 Recall 可到 60%+）。

OpenAI Mod FPR 改善路径：加 WildGuardMix / XSTest 英文 safe 数据 + soft rules for 教育场景，预计 FPR 可从 18.7% 降到 10% 以内。延迟保持 ~6ms 优势不受影响。
